# Решение

Состав HR-адресатов задаётся централизованно в настройках, не копированием
карточек во все шаги. Основная HR Telegram identity остаётся отдельной.
Дополнительные карточки используют employee tokens существующего поля,
разрешаются по актуальной подтверждённой привязке и не дают прав HR в боте.

По явному запросу пользователя для карточки78 нужен режим наблюдателя:
копии настроенных служебных уведомлений HR/руководителю/наставникам.
Его включают отдельно для выбранного сотрудника; состав меняет только admin.
Обычные сообщения, шаги, ответы и OTP сами по себе не зеркалируются.
Если наблюдатель уже входит в адресаты правила, повторная копия не отправляется.

Данные хранятся в hr_settings.notification_recipient_ids без новых колонок:
employee:<id> — дополнительный HR, observer:employee:<id> — явные копии
остальных служебных notification rules. Удаление привязки/блокировка/архив
исключает адресата при доставке. Исторические сценарные scopes не переписываются.
