# Решение

Для заранее заведённых сотрудников Telegram username используется только для поиска карточки. Доступ даёт лишь одноразовый код, отправленный на уникальную рабочую почту карточки. Подтверждение привязывается к числовому Telegram ID. Старые numeric-привязки сотрудников требуют повторной проверки; смена ID после подтверждения требует operator reset. Отдельные персональные ссылки для первой волны не нужны, поскольку актуальные username уже заполнены.

Кандидатский `/start` и отдельная HR Telegram deep-link привязка сохраняют свои правила. Код по email подтверждает контроль рабочего ящика для первоначальной привязки; он не заявляется как сильная многофакторная аутентификация. Пока SMTP не настроен или письмо не доставлено, доступ сотруднику не выдаётся.
