# Решение

Портировать домен Design Grade в HRBot, не связывать приложения через cookie-сессию.
Источник: `arctand/grade@a360e5083b6608dbeceb1038769c5280936fe7c0`.
Reference checkout используется только для чтения. CSS, тема и auth Grade не переносятся.

`Person` заменён на `employees`; `Workspace`, `User`, `Session`, `LoginAttempt`,
`ArchiveItem` не переносятся. Справочники архивируются флагом `active`, без физического
удаления навыков и истории оценок. Оператор использует существующую авторизацию HRBot.

Специализация оценки и кадровая должность остаются разными сущностями.
Опциональное `grade_specializations.position_slug` ссылается логически на `positions.slug`.
Совпадение предлагает специализацию, но не записывает профиль без действия оператора.
Поля цели добавлены в профиль сотрудника, поскольку цель существует и до создания оценки.

Новые таблицы создаются additive через модели и SQLite compatibility; существующие
таблицы не перестраиваются ради Grade. Seed создаёт только четыре стандартных грейда,
а каталог дизайнеров импортируется явно. Финальная оценка хранит снимок каталога,
значений и вычисленной view-модели. Изменения справочников не переписывают историю.

Для SQLite запись Grade сериализуется `BEGIN IMMEDIATE` до чтения данных, включая
создание черновика, сохранение значений и финализацию. Частичный unique-index допускает
один черновик на сотрудника. Автоматического повышения кадрового грейда нет.

Backend и UI поставляются отдельно; `GET /api/employees/{employee_id}/grade`
не зависит от employee-detail bootstrap. Это API для будущего ЛК, но сейчас оно
доступно только авторизованным операторам; employee self-service auth не добавляется.

CI/workflow в этом пакете не меняются без согласования интегратора. Новые тесты
выполняются локально и должны быть добавлены в CI smoke отдельным согласованным изменением.
