# Сопоставление должностей

Этот срез не добавляет Employee.position_id, aliases schema или массовую миграцию.
`positions.slug` — ключ выбора аудитории, `positions.title` — отображаемое имя;
`employees.desired_position` остаётся совместимым текстовым значением.

Для ORM-записей с Session scenario/menu runtime и адаптационный PM-фильтр
разрешают значение через текущий каталог. Для текста карточки сначала ищется
уникальное точное название (casefold и пробелы), затем slug/существующие legacy
aliases. Для role_scope первичен точный ключ slug: совпадение с названием другой
должности не должно подменять выбранную сущность. Неоднозначность не разрешается
произвольной первой строкой. Unknown legacy значения сохраняют прежний fallback,
`all` не меняется. Detached/test значения без Session используют прежнее правило.

SQL массового выбора включает реальные текстовые варианты карточек, которые
принимает тот же resolver; поэтому одиночный role scope, multi-select и runtime
не расходятся только из-за регистра, пробелов или custom slug. Блокировки,
employee/candidate scope, адресные ID и взаимное исключение групп/людей сохраняются.
Inactive скрывается из новых UI choices, но сама по себе не отменяет старые
role-scoped запуски: этот прежний контракт не меняется.

Каталог кешируется в пределах текущей Session transaction; commit и операции
ensure_position_exists сбрасывают snapshot. Startup не переименовывает и не
активирует управляемые строки; defaults устанавливаются только в пустой каталог
без сотрудников. Startup не собирает новые должности из карточек.

Create/update API отклоняет duplicate title после casefold/нормализации пробелов
с 409, включая конфликт с inactive строкой. Existing конфликтующие строки не
объединяются. Редактор карточки принимает пустое значение либо уникальную активную
позицию по ID, точному slug или названию (casefold/пробелы). Unknown/inactive
отклоняется; save больше не создаёт позиции. Options карточки и сценария берутся
из активного каталога, без свободных исторических значений. Legacy runtime matching
не меняется этим ограничением редактора.

## Ограничения и приёмка

Переименование через settings API сохраняет неизменный slug. В той же
транзакции текущие Employee.desired_position со старым точным названием
(casefold/пробелы) обновляются на новое. Исторические события, оценки и тексты
не переписываются; сценарии/меню/сохранённые аудитории продолжают ссылаться на
тот же slug. Ошибка commit откатывает каталог и карточки вместе.
Смена slug возвращает 409. Неоднозначное старое название или новое название,
уже использующееся в других карточках, также требует явного mapping (409).
Новых сохранённых aliases нет: последующий импорт старого свободного названия
остаётся отдельным сопоставлением, а не неявным объединением должностей.

Произвольные сокращения вроде «рук проектов» не объявляются автоматически
синонимом «Руководитель проектов». Для исторического rename с custom slug может
понадобиться явный mapping; старое имя не выдумывается из новой строки каталога.
Copy/portability сохраняют существующие slug-значения, новых полей схемы нет.
Должность не назначает системную роль HR/admin или флаг руководителя.

## Объединение руководителей проектов

Подтверждён только mapping project_manager/rukovoditel_proekta в
rukovoditel_proektov («Руководитель проектов»). Admin maintenance page
`GET /app/settings/positions/consolidate-project-leads` показывает read-only
preview без PII. POST той же страницы принимает fingerprint и same-origin form;
делает SQLite backup/quick_check, BEGIN IMMEDIATE и повторный preview. Drift или
изменение projected role-аудиторий блокирует применение. Обновляются текущие
карточки, scopes сценариев/меню, Grade position_slug и только необработанные
массовые рассылки (single/JSON multi). Старые позиции деактивируются, не удаляются.
Обработанные рассылки, history/snapshots не переписываются. Повторный preview
должен давать пустой changes. Это не симуляция доставки и не запуск сценариев.

Перед интеграцией/выкладкой нужен read-only preview текущих аудиторий:

```powershell
python tools/audit_position_matching.py --db <consistent-local-copy.db>
```

Tool открывает существующую SQLite через mode=ro; не вызывает init_db, seed,
commit или ALTER. Выводит aggregate должностей и различающиеся recipient IDs
для position filtering сценариев, без ФИО/почты/сообщений. Это не симуляция
trigger/delivery/прав доступа. Preview не является командой применения.
Для live-stage использовать согласованную консистентную копию, не замену БД.
При неоднозначном mapping сначала согласовать решение; до preview пакет не
считать готовым к изменению реальных аудиторий.
