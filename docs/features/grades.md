# Грейды

Стандартные четыре грейда создаются только при пустом справочнике. Последующий
перезапуск не восстанавливает переименованные записи. Финализация требует активных
специализации, текущего и целевого грейдов; архивная цель должна быть изменена до
финализации. Уже финализированные снимки от изменений справочника не зависят.

При равных числовых приоритетах сортировка названий использует порядок Unicode,
а не localeCompare исходного Grade; формулы расчёта от этого не меняются.

Backend port Design Grade из `arctand/grade@a360e50`: глобальные категории/навыки,
специализации, матрица ожиданий по грейдам, профили сотрудников и история оценок.
Настройки UI и вкладка сотрудника поставляются отдельной dependency-веткой поверх backend.

## Интерфейс оператора

`/app/grades` доступен из бокового меню. Вкладки: матрица, грейды, специализации,
категории, навыки, импорт. Справочники редактируются в диалогах; архивирование требует
подтверждения. Матрица сохраняет только изменённые строки. Смена специализации
блокируется до сохранения или сброса изменений. JSON можно загрузить файлом или
вставить текстом: сначала предпросмотр, затем подтверждённое применение.

В карточке сотрудника есть вкладки «Профиль» и «Грейд». Переключение не сбрасывает
формы. Вкладка загружается при первом открытии. Профиль грейда, цель и история читаются отдельным API. Оценка показывает
уровни 0–4, профиль категорий, прогресс и зоны развития; расчёты обновляются после
явного сохранения. Финализация недоступна при несохранённых изменениях и требует
подтверждения. Финальная оценка открывается только для чтения из снимка.

Представление уровней и профиля категорий:

- в черновике уровень выбирается переключателем `0..4`; выбранное значение
  дублируется подписью (`2 · Умение`), подписи уровней: `0 Нет`, `1 Понимание`,
  `2 Умение`, `3 Экспертиза`, `4 Лидерство`;
- в финальной оценке уровень показывается текстом `2 · Умение`, а не
  disabled-переключателем: для screen reader это значение «Уровень: …», без
  обещания редактирования;
- профиль категорий при трёх и более категориях — радар с ограниченным размером
  (не зависит от ширины одноколоночной раскладки); при одной–двух категориях —
  пара полос «Текущий / Цель» на категорию; без категорий — текстовое пустое
  состояние. Текущий и целевой ряды различаются легендой и стилем (сплошной /
  пунктир), не только цветом. Длинные подписи осей сокращаются, полные названия
  есть в списке категорий под диаграммой. Числа не зависят от представления.

В таблице специализаций должность показывается названием из справочника
`positions` (в API и storage остаётся `position_slug`): пустая привязка —
«Не привязана», архивная должность — название с пометкой «(архив)», slug без
записи в справочнике — сам slug с пометкой «(нет в справочнике)».

Паттерн карточки с вкладками: `/app/design-system#record-with-tabs`.
Светлая и тёмная темы используют существующие семантические токены HRBot.

## Расчёты

- Уровень навыка: целое `0..4`. На входе API дроби и значения вне диапазона отклоняются.
- Важность `1/2/3` имеет вес `1/1.5/2`.
- Среднее категории: сумма уровня, умноженного на вес, делённая на сумму весов.
- Прогресс к цели: `sum(min(current, target) * weight) / sum(target * weight)`.
  Нулевая сумма требований даёт 0. При выбранной цели результат API в диапазоне `0..1`, не проценты; без цели `progress=null`, список пробелов пуст.
- Пробел: `max(0, target-current)`; сортировка по взвешенному пробелу, важности, названию.
- Цель: нет, грейд в текущей специализации или грейд другой специализации.
  Совпадающая с текущей целевая специализация нормализуется в обычную цель по грейду.

## Жизненный цикл

GET профиля не создаёт запись. Оператор назначает специализацию/текущий грейд и цель.
POST оценки возвращает существующий черновик либо создаёт новый с переносом значений
предыдущей оценки. При смене целевой специализации используется её матрица.
Финализация замораживает view-модель, включая подписи и расчёты. Повторная финализация
идемпотентна; PATCH финальной оценки запрещён. Изменения каталога после финализации
не меняют результат GET истории. Повышение грейда остаётся отдельным решением оператора.

Удаление карточки с финализированной оценкой запрещено (HTTP 409) до отдельного
решения об архиве/хранении истории. Проверка выполняется под write lock до удаления
файлов или связанных записей. Если финальных оценок нет, общий путь удаления карточки
удаляет также профиль грейда, черновики и их значения; чужие оценки не затрагиваются.

Категории глобальны. Изменение названия/архивация навыка отражается на живых матрицах
всех специализаций, но не на снимках финальных оценок. Удаление справочника означает
`active=false`, а не физическое удаление строк. Новые пары получают importance=1,
expectation=0; существующие значения не перезаписываются дефолтами.

## Импорт

`POST /api/grades/import` принимает `dryRun`, `mode` (`create-specialization` или
`update-specialization`), `targetSpecializationId` для обновления и `catalog`.
Формат совместим с Grade `CATALOG_IMPORT_GUIDE.md`:

```json
{
  "dryRun": true,
  "mode": "create-specialization",
  "catalog": {
    "specialization": {"name": "Дизайн"},
    "categories": [{"name": "Композиция", "skills": [{
      "name": "Визуальная иерархия", "importance": "critical",
      "levels": {"junior": 1, "middle": 2, "senior": 3, "lead": 4}
    }]}]
  }
}
```

Важность: `1..3` или `ordinary/key/critical`; уровни `0..4`, строковые числа,
`none`/`нет` для нуля. Дубли категорий/навыков внутри файла и неверные уровни отклоняются.
Сначала предпросмотр без записи, затем явное применение. Импорт целиком транзакционный,
не удаляет отсутствующие в файле данные. Пример полного каталога из reference seed:
`tools/data/grade-design-catalog.json`. Автоматически при запуске он не импортируется.

## Проверки

`tests.test_grade_calculations`, `tests.test_grade_goals`, `tests.test_grades_services`,
`tests.test_grades_api_smoke` дополняют обязательные проверки HRBot. Live DB не нужна:
используется отдельная SQLite и фиктивный Telegram token. Визуальная приемка относится
к UI-пакету: light/dark, создание специализации, импорт, оценка, финализация.
